01 · O DESAFIO

Quando o mesmo dado aparece mais de uma vez

Imagine uma instituição de ensino que precisa manter milhares de registros de estudantes organizados e confiáveis.

Durante o processo de matrícula, atualização cadastral ou importação de informações, um mesmo estudante pode acabar registrado mais de uma vez.

Essas duplicidades podem comprometer a consistência das informações e afetar relatórios e análises.

A pergunta central deste estudo é: como identificar registros duplicados e estabelecer critérios para classificar o registro prioritário de cada aluno?

EXECUTIVE SUMMARY

Da identificação à tomada de decisão

A análise dos cadastros escolares identificou 15 registros associados a 10 alunos distintos, evidenciando a existência de registros adicionais para alunos já presentes na base de dados.

Por meio de consultas SQL e da função ROW_NUMBER(), foi desenvolvida uma lógica de classificação que considera o status da matrícula, a data do registro e o identificador como critérios de prioridade.

Como resultado, foram selecionados 10 registros prioritários e identificados 5 registros adicionais, correspondentes a 33,33% do volume total analisado.

A regra aplicada priorizou matrículas com status ativo e, em seguida, os registros mais recentes. Essa abordagem permitiu organizar os dados e identificar possíveis duplicidades de maneira estruturada, sem realizar exclusões automáticas.

Recomendação: validar os registros classificados como possíveis duplicidades junto às regras de negócio da instituição antes de qualquer atualização ou exclusão, evitando a perda de informações legítimas.

05 · SQL INSIGHTS

O pensamento por trás dos dados

Consultas SQL desenvolvidas para investigar, classificar e compreender os registros da base de dados.

QUERY 01

Data Overview

Quantificação dos registros e identificação da quantidade de alunos distintos na base. 

SELECT
    COUNT(*) AS total_registros,
    COUNT(DISTINCT id_aluno) AS total_alunos
FROM cadastros_escolares;
Resultado: 15 registros e 10 alunos distintos.
COUNT() · DISTINCT
QUERY 02

Duplicate Detection

Identificação dos alunos que possuem mais de um registro na tabela. 

SELECT
    id_aluno,
    nome_aluno,
    COUNT(*) AS quantidade
FROM cadastros_escolares
GROUP BY id_aluno, nome_aluno
HAVING COUNT(*) > 1;
Resultado: 5 alunos identificados com múltiplos registros.
GROUP BY · HAVING
QUERY 03

Record Classification

Classificação sequencial dos registros de cada aluno, permitindo identificar ocorrências repetidas. 

SELECT
    id_aluno,
    nome_aluno,
    id_registro,

    ROW_NUMBER() OVER (
        PARTITION BY id_aluno
        ORDER BY id_registro
    ) AS ordem

FROM cadastros_escolares;
Resultado: Numeração individual dos registros de cada aluno.
ROW_NUMBER() · PARTITION BY
QUERY 04

Business Rules

Aplicação de critérios de prioridade para selecionar um registro por aluno 

SELECT *
FROM (
    SELECT
        id_registro,
        id_aluno,
        nome_aluno,
        data_matricula,
        escola,
        status,
        ROW_NUMBER() OVER (
            PARTITION BY id_aluno
            ORDER BY
                CASE
                    WHEN status = 'Ativo' THEN 1
                    ELSE 2
                END,
                date(data_matricula) DESC,
                id_registro DESC
        ) AS ordem_prioridade
    FROM cadastros_escolares
) AS registros_classificados
ORDER BY id_aluno, ordem_prioridade;
Resultado: 10 registros prioritários e 5 registros adicionais classificados
CASE WHEN · ORDER BY
